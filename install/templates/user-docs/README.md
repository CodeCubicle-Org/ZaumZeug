## Quick links

- **`zaumzeug init <name>`** — scaffold a new harness under `usr-harnesses/`
- **Custom tools** — list Python modules in `tools.custom` on `agent.yaml` (`agents/<name>/tools/*.py`). Import errors fail `zaumzeug doctor` / serve with the module path. SDK builtins (`web_fetch`, `calculator`, `read_file`, `search_docs`) use `tools.builtin` instead. `search_docs` needs a RAG pipeline in `serve.expose` — see [Pipelines and RAG](guides/pipelines.md) and [Custom tools](guides/custom-tools.md).
- **`zaumzeug mcp <harness>`** — serve the workflow entry agent as MCP at `http://127.0.0.1:{mcp_port}/mcp` (default **1417**). Production: `zaumzeug mcp <harness> --deploy` (or `HARNESS_ROOT=deploy`). Point Cursor at that URL via `.cursor/mcp.json` (install `--cursor-mcp` or copy the example). Declare external MCP servers in `tools.mcp` on `agent.yaml` (Haystack `MCPToolset`; stdio servers need `uv`). See [Cursor MCP setup](guides/cursor-mcp.md), [Deploy and ship](guides/deploy.md), and [CLI — mcp](reference/cli.md#zaumzeug-mcp).
- **`zaumzeug acp <harness>`** — Agent Client Protocol stdio JSON-RPC for Zed / JetBrains (the IDE drives the harness as the primary agent). Not IBM ACP/A2A. Cursor uses MCP, not ACP. See [ACP (Zed / JetBrains)](guides/acp.md) and [CLI — acp](reference/cli.md#zaumzeug-acp).
- **`zaumzeug a2a <harness>`** — optional Agent2Agent hosting when `serve.a2a: true` (`pip install "hayhooks[a2a]"`). Agent card at `http://127.0.0.1:1418/{harness}/.well-known/agent-card.json`. Separate from MCP and ACP; one harness per process (NG1). See [A2A](guides/a2a.md) and [CLI — a2a](reference/cli.md#zaumzeug-a2a).
- **`zaumzeug serve <harness>`** — interactive chat with the workflow **entry** agent (dev: `usr-harnesses/`). Use **`--deploy`** or **`HARNESS_ROOT=deploy`** to serve a production bundle from `deploy/<name>/` only (E5-S03 / E5-S04) — same OpenAI REST API; no `usr-harnesses/` required. Pipelines listed in **`serve.expose`** are also served as **`POST /{id}/run`** (E8-S01). Optional **`serve.hayhooks.chainlit: true`** serves Chainlit at `/chat` on the same port (`pip install "hayhooks[chainlit]"`). Other web clients (Open WebUI, SPA + Nginx, Next.js) use `baseURL` `http://127.0.0.1:1416/v1` (not `api.openai.com`). Production HTTP is **unauthenticated in Hayhooks** — put Traefik (or Nginx/Caddy) in front ([Production auth](guides/production-auth.md), E8-S02). Opt-in production trace capture (`eval.trace_capture` / `ZAUMZEUG_TRACE_CAPTURE`) writes Haystack turns to `data/traces/` (E8-S03). Opt-in Mode B Confident AI sync (`eval.confident_ai.enabled`) wraps serve with DeepEval `@observe` (E8-S06 — needs `[eval]` + login). See [CLI — serve](reference/cli.md#zaumzeug-serve), [Pipelines and RAG](guides/pipelines.md), [Web deployment](guides/web-deployment.md), [Testing — Journey C](guides/testing.md#trace--test-case-journey-c), [Testing — Mode B](guides/testing.md#mode-b--deepeval-observe--confident-ai-opt-in), [Global environment](reference/cli.md#global-environment), and the bundle's `README.deploy.md`.
- **`zaumzeug run <harness>`** — run serial workflow stages in order (agent stages plus **`pipeline:`** YAML from `serve.expose` — E8-S01); optional `runtime.retry` / `output.format: json` / stage INFO logs (`HARNESS_LOG_LEVEL=INFO`) — see [Run reliability](guides/multi-agent-workflow.md#run-reliability-zaumzeug-run) (E8-S07; serve/HTTP does not share this layer yet) and [Pipelines and RAG](guides/pipelines.md). Optional **`--rate`** rates the last agent stage after the run (E6-S08).
- **`zaumzeug rate`** — human quality rating for a harness (`zaumzeug rate <harness>`) → gold → optional `--apply` / `--compile` (E6-S08). Rates a `--trace` or one `--unrated` stem; writes `data/ratings/`; merges into val/train; no DeepEval required. See [Testing — Human quality rating](guides/testing.md#human-quality-rating--recompile) and [CLI — rate](reference/cli.md#zaumzeug-rate).
- **`zaumzeug compile <harness>`** — run GEPA per agent (Phase 2, Pattern A); writes immutable `artifacts/<run_id>/` + `current` with Haystack export (`artifact-manifest.json`, prompts); regenerates `docs/workflow-diagram.md` (or use `--workflow-diagram-only`); use `--dry-run` to validate modules/registry without GEPA or LLM calls; pin/rollback to a prior run without re-GEPA — see [Compile and export — Rollback](guides/compile.md#rollback-to-a-pinned-run); optional `input_rewrite` is applied at serve/run time; Pattern B (`optimize_anything`) is available via `optimize_haystack_artifact` (E4-S04); live task/reflection models need API keys in `.env` (example uses mock/stub offline). See [Compile and export](guides/compile.md).
- **`zaumzeug eval <harness>`** — optional harness regression (E6-S02): `eval.framework: builtin` JSONL checks (no DeepEval) or `deepeval` metrics (needs `pip install "zaumzeug[eval]"`); CLI `--framework` override. Score a captured turn with `--trace data/traces/….jsonl` (E6-S05) without re-running the agent. Production serve can auto-capture those traces (`eval.trace_capture` / `ZAUMZEUG_TRACE_CAPTURE`); merge into `data/val.jsonl` / `data/train.jsonl` with `merge_traces_into_datasets` (E8-S03). Black-box a running serve with `--base-url` (Mode C / E6-S06) — staging/debug only. Optional `eval/` pytest scaffold via `zaumzeug init --with-eval` or the example harness — `deepeval test run usr-harnesses/<name>/eval/` (E6-S04). Failed eval → GEPA train via `append_failed_eval_to_train`; shared valset + optional DeepEval GEPA metrics in `modules/metrics.py` (E6-S07). Opt-in production `@observe` / Confident AI when `eval.confident_ai.enabled` (E8-S06). See [Testing](guides/testing.md) (incl. [Journey C](guides/testing.md#trace--test-case-journey-c), [Human quality rating](guides/testing.md#human-quality-rating--recompile), [Mode B](guides/testing.md#mode-b--deepeval-observe--confident-ai-opt-in), [Mode C](guides/testing.md#mode-c--http-black-box-stagingdebug), and [GEPA ↔ DeepEval bridge](guides/testing.md#gepa--deepeval-bridge-compile--eval--compile)) and [CLI — eval](reference/cli.md#zaumzeug-eval).
- **`zaumzeug deploy <harness>`** — doctor preflight, eval gate (`deploy.eval_gate` / `--eval-gate`), then write `deploy/<name>/` (E5-S01 + E5-S02 copy matrix): stripped yaml, pinned artifacts, no `modules/`/`data/`/`eval/`/`skills/`, `manifest.json`, `README.deploy.md`, target install scripts. Optional `Dockerfile` (+ `.dockerignore`, `docker-compose.example.yml`) with `--dockerfile` or `deploy.dockerfile: true` (E8-S05). Ops then: copy bundle → `target_install` (venv / runtime `pip install zaumzeug` / `.env` seed / wrappers / optional `--verify` — **Done** E5-S09a/b/c) → `.env` → `zaumzeug serve <name> --deploy` or `zaumzeug mcp <name> --deploy` or `HARNESS_ROOT=deploy` (E5-S03–S05, E7-S06). See [Deploy and ship](guides/deploy.md), [CLI — deploy](reference/cli.md#zaumzeug-deploy), and [Testing — deploy gates](guides/testing.md).
